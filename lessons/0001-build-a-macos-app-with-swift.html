01

The terrain

A Mac app is a small graph of responsibilities.

Xcode shows many files and settings, but ClipFetch’s application code has five jobs. Learn these boundaries first; syntax becomes easier when you know why each line exists.

ClipFetchApp.swift → ContentView.swift

App shell & interface

The entry point creates one window. The root view reads its state and describes the screen that belongs to that state.

SourceURL.swift

Input boundary

Turns untrusted text into a validated HTTP or HTTPS URL—or returns nothing.

MediaDetails.swift

Domain values

Names the information the UI needs: title, duration, size, resolution, and quality.

YTDLPInspector.swift

Inspection service

Runs the bundled command away from the UI, then decodes its JSON output.

YTDLPDownloader.swift

Download service

Starts and cancels the process, parses progress, and moves the completed file.

The first useful mental model: the view does not download anything. It changes state and asks a service to do work.
Read in this order
ClipFetchApp.swift → ContentView.swift → SourceURL.swift → the model → the two services. Follow the user action, not the alphabetical file list.
02

The language

Eight Swift ideas read most of this app.

Swift is strongly typed, but it infers obvious types. Its sharpest feature is that absence, failure, and state choices are visible in the code instead of hiding as conventions.

let / var

Values

let names a value that will not be reassigned. var names one that can change. Prefer let; mutation should be easy to spot.

struct

Value types

Models and SwiftUI views are usually structures. Passing one gives independent value semantics, which keeps small types predictable.

enum

Finite choices

An enum lists valid cases. A case can carry data, so .completed(URL) means “complete” always includes the saved file.

URL?

Optionals

The question mark means a value may be absent. Swift makes you unwrap it before use, preventing a large class of null errors.

guard … else

Early exits

A guard checks what must be true and leaves early otherwise. The successful path stays flat and readable.

func

Functions

Functions name behavior, parameters name inputs, and -> introduces a returned type. Methods are simply functions attached to a type.

async / await

Suspension

An async function may pause without freezing the interface. await marks the exact call where that pause may occur.

throws / try

Failure

A throwing function can fail with an error. try marks the call; do/catch decides what the app shows next.

SourceURL.swift · a trust boundary
enum SourceURL {
    static func parse(_ value: String) -> URL? {
        let trimmed = value.trimmingCharacters(in: .whitespacesAndNewlines)

        guard let url = URL(string: trimmed),
              let scheme = url.scheme?.lowercased(),
              ["http", "https"].contains(scheme),
              url.user == nil,
              url.password == nil,
              url.host != nil else {
            return nil
        }

        return url
    }
}
Say it aloud
“Parse takes a String and returns either a URL or no value. The guard unwraps the possible URL and scheme, checks the allowed schemes and host, then exits with nil if any condition fails.” If you can narrate types and branches, you can read Swift.
MediaDetails.swift · an enum with associated values
enum QualityOption {
    case best
    case resolution(width: Int, height: Int)

    var displayName: String {
        switch self {
        case .best:
            "Best"
        case let .resolution(width, height):
            "\(width) × \(height)"
        }
    }
}

displayName is a computed property: it derives text instead of storing duplicate state. The switch must handle every case, so adding a future case produces useful compiler errors wherever behavior is missing.

03

The framework

SwiftUI is state transformed into a view.

You do not imperatively create a label and later hunt it down to change its text. You describe what the whole interface should look like for the current data; SwiftUI updates the necessary parts.

ClipFetchApp.swift · process entry point
import SwiftUI

@main
struct ClipFetchApp: App {
    var body: some Scene {
        Window("ClipFetch", id: "main") {
            ContentView()
        }
        .windowResizability(.contentSize)
    }
}
Translate it
@main marks where the process starts. App is a protocol—a capability contract. To satisfy it, the type supplies a body containing a scene. This scene is one Mac window whose root is ContentView.

ContentView.swift · state chooses the screen
struct ContentView: View {
    @State private var viewState = ViewState.urlEntry

    var body: some View {
        switch viewState {
        case .urlEntry:
            urlEntry
        case .inspecting:
            inspectionInProgress
        case .details(let details):
            mediaDetails(for: details)
        case .downloading(let details, let quality, let status):
            downloadInProgress(for: details, quality: quality, status: status)
        case .completed(let fileURL):
            downloadCompleted(fileURL: fileURL)
        case .failed(let message, let diagnostics, let details):
            downloadFailed(message: message, diagnostics: diagnostics, details: details)
        }
    }
}

@State gives SwiftUI storage for view-owned mutable data. When viewState changes, SwiftUI evaluates body again. ClipFetch makes impossible combinations unrepresentable by using one enum instead of many booleans.

.urlEntry.inspecting.details(MediaDetails).downloading(…).completed(URL).failed(…)
ContentView.swift · asynchronous action
private func requestInspection() {
    guard let url = SourceURL.parse(sourceURL) else { return }
    viewState = .inspecting

    Task {
        do {
            let details = try await YTDLPInspector().inspect(url)
            viewState = .details(details)
        } catch {
            viewState = .failed(
                message: error.localizedDescription,
                diagnostics: nil,
                details: nil
            )
        }
    }
}
The loop
Validate → show immediate progress → start an async task → await the service → turn success or failure into a new state. This is the reusable spine of many Mac utilities.
04

The practical win

Build ClipFetch Lite.

This tiny app accepts a web address, validates it, waits briefly to simulate inspection, and shows the host. It keeps the same architecture without the bundled command-line tools.

Create the project

Open Xcode and choose File › New › Project…. Select macOS › App. Name it ClipFetchLite, choose SwiftUI for Interface and Swift for Language, then save it.

Keep the generated app file

Xcode already creates the entry point. It should look like this; the template has done the ceremony for you.

ClipFetchLiteApp.swift
import SwiftUI

@main
struct ClipFetchLiteApp: App {
    var body: some Scene {
        WindowGroup {
            ContentView()
        }
    }
}

Replace ContentView

This is a complete small interface. Notice the same loop as ClipFetch: local state, input validation, progress, async work, result.

ContentView.swift
import SwiftUI

struct ContentView: View {
    @State private var source = ""
    @State private var state = InspectionState.ready

    var body: some View {
        VStack(alignment: .leading, spacing: 20) {
            Text("ClipFetch Lite")
                .font(.largeTitle.bold())

            TextField("https://example.com/video", text: $source)
                .textFieldStyle(.roundedBorder)
                .onSubmit(inspect)
                .disabled(state == .inspecting)

            switch state {
            case .ready:
                Text("Enter a public web address.")
                    .foregroundStyle(.secondary)
            case .inspecting:
                ProgressView("Inspecting…")
            case let .found(host):
                Label("Ready: \(host)", systemImage: "checkmark.circle.fill")
                    .foregroundStyle(.green)
            case .invalid:
                Label("Enter a valid HTTP or HTTPS URL.", systemImage: "exclamationmark.triangle")
                    .foregroundStyle(.red)
            }

            Button("Inspect", action: inspect)
                .buttonStyle(.borderedProminent)
                .disabled(state == .inspecting)
        }
        .frame(width: 420)
        .padding(28)
    }

    private func inspect() {
        guard let url = URL(string: source),
              let scheme = url.scheme?.lowercased(),
              ["http", "https"].contains(scheme),
              url.user == nil,
              url.password == nil,
              let host = url.host else {
            state = .invalid
            return
        }

        state = .inspecting
        Task {
            try? await Task.sleep(for: .seconds(1))
            state = .found(host)
        }
    }
}

private enum InspectionState: Equatable {
    case ready
    case inspecting
    case found(String)
    case invalid
}

Run and interrogate it

Press ⌘R. Try a valid URL, plain text, and a URL without a host. Then set a breakpoint on state = .inspecting and run again. Watching one action cross that line is worth more than memorizing a page of syntax.

The window opens and accepts typing.
Invalid text shows an error.
A web URL shows progress first.
The final label includes the host.
